# Numeric studies: numbers before circuits

A numeric task can start from frozen data, a checkpoint and an unchanged host
verifier. It does not need a circuit generator or a chemistry-specific adapter.
First account for the error budget and the discrete resource tradeoffs; then
run bounded numeric experiments, package a promising artifact, and use the
existing independent host gates. Circuit rewrites remain an optional later step.

The APIs below are in [numeric.py](../src/strata/numeric.py). Resumable workers,
portfolio bets and final certification are documented by
[numeric_jobs.py](../src/strata/numeric_jobs.py); convergence forecasts, stop
diagnostics and local quadratic models are in
[the numeric models guide](V0.3-NUMERIC-MODELS.md) and
[numeric_models.py](../src/strata/numeric_models.py). Model forecasts and
worker-reported observations do not themselves certify host acceptance.

## Error leaves and evidence

Every value has `value`, `unit` and `evidence_kind`: `measured`, `fitted_trend`,
`model` or `judgment`. Hash provenance is mandatory. A measured value also needs
an `artifact_hash` whose actual bytes can be read and rechecked in the Store.
Other kinds never become measurements merely because their values are precise.
Units are exact caller labels; this layer does not silently convert units.

```python
from strata.store import Store
from strata.numeric import EvidenceValue, error_budget

store = Store("/tmp/strata-numeric-study")
source = store.blob(b"declared illustrative additive error model, version 1")

def model(value):
    return EvidenceValue(value, "error", "model", source_hash=source)

ledger = error_budget(
    [
        {"id": "fit", "evidence": model(0.30),
         "labels": {"stage": "fit", "source": "do"}},
        {"id": "tail", "evidence": model(0.40),
         "labels": {"block": "second", "source": "oo"}},
        {"id": "cross", "evidence": model(-0.10),
         "role": "cross", "cross_of": ["fit", "tail"]},
        {"id": "round", "evidence": model(0.05), "role": "rounding"},
    ],
    unit="error", limit=0.80, store=store,
    groups={"fit_view": ["fit", "cross"],
            "tail_view": ["tail", "cross"],
            "total": ["fit_view", "tail_view", "round"]},
    roots=["total", "fit_view"],
)
assert abs(ledger["total"] - 0.65) < 1e-12
```

Groups reference leaves rather than adding a second subtotal. The cross term
and fit term each count once despite overlapping views. Labels such as stage,
block, source, `do` and `oo` have no built-in mathematical meaning. Negative
contributions require an explicit cross term and referenced component leaves.
An inconsistent negative total is rejected rather than called an error bound.

The ledger's `allowed_rounding_budget` is 0.20, conditional on the recorded
nonrounding and cross terms. Changing rounding can change cross terms, so this
headroom is not a new feasibility proof. `remaining` includes existing rounding
and is 0.15. The ledger preserves evidence tiers and hashes separately.

## Map a discrete design space with the real formula

```python
from strata.numeric import design_space, break_even_scale

def resources(shape, context):
    width = shape["width"]
    return {"Q": 4 if width <= 3 else 9,
            "work": 12 - width, "fixed": context["fixed"]}

model_source = store.blob(
    b"model: Q=4 for width<=3 else 9; work=12-width; fixed from context"
)
space = design_space(
    {"width": [2, 3, 4]}, formula="Q*work+fixed",
    resource_hook=resources, source_hash=model_source,
    context={"fixed": 7}, store=store, max_points=16,
)
assert [point["cost"] for point in space["points"]] == [47, 43, 79]
assert space["best"]["settings"] == {"width": 3}

threshold = break_even_scale(
    "costscale*(Q*work)+fixed", {"Q": 3, "work": 7, "fixed": 4},
    scale_parameter="costscale", target=46, linear_scale=True,
)
assert threshold["break_even"] == 2
```

The width jump is retained exactly; no smooth interpolation hides it. The hook
above returns model resources, so every point remains `model`. In a real study,
pin the actual resource-hook source bytes and the full input context. Supply
the caller's exact `Formula`, including its full objective and resource keys.
An optional `budget_hook(settings, context)` supplies a hashed `error_budget`
ledger; over-budget points are excluded from `best` under that stated model.

A trusted verifier hook may instead return `ResourceReceipt`. The checked
receipt binds resources, artifact bytes, pinned verifier source, context hash,
settings hash, pass/fail and the exact stored receipt payload. A mismatched
shape, context, source or resource payload is rejected. This is a trusted
runner interface, not an attestation that arbitrary caller code is trustworthy.
Rejected verifier points are retained and cannot become `best`.

`break_even_scale` requires an explicit linear-scale declaration and checks the
expression structurally. Scale-dependent nonlinear functions, products, powers,
denominators and context-aware hooks are rejected. The threshold is an
algebraic model with the other resource values fixed, not a measured gain.

## Shared experiments and missing combinations

`NumericStudy(store)` stores immutable `numeric_experiment` records. Different
agents can open the same Store and query newly committed experiments. Each
record binds a contract, base artifact, output artifacts, settings, factors,
line identity, sibling lines and named evidence-valued observations.

```python
from strata.numeric import NumericStudy

study = NumericStudy(store)
# After the trusted runner supplies observations and its checked receipt:
# handle = study.record(
#     contract=contract, base=base_hash, artifacts={"output": artifact_hash},
#     settings=settings, factors=factors, line="fit-A", siblings=["fit-B"],
#     observations=observations, baseline=baseline_handle,
#     verifier_receipt=receipt, verifier_hash=pinned_verifier_hash,
# )

suggestions = study.suggest_transfers(
    line="fit-B", contract="frozen-host-contract",
    factors={"family": "same-mathematics", "block": "right"},
    transfer_keys=["block"],
)
combinations = study.combinations(
    line="fit-B", contract="frozen-host-contract",
    factors={"family": "same-mathematics", "block": "right"},
    transfer_keys=["block"], max_terms=2, max_candidates=32,
)
```

A source win requires passed, checked verifier receipts for the experiment and
its baseline, plus an improved measured metric in matching units. An unverified
claim or fitted prediction cannot trigger a tested-win suggestion. Baseline
comparisons freeze the contract, base and factors. Stored artifacts and receipt
bindings are rechecked when experiments are read.

By default transfers require exact factors and contract. `transfer_keys` permits
only named factor values to vary across sibling contexts; the example allows
the block to change while keeping the family fixed. Source and target factors
remain visible. Every transfer is explicitly a hypothesis with no target gain
established. Even if two winning settings were tested individually on the
target, `combinations` can propose their still-untested joint setting. Conflicting
settings are excluded, and exhausted enumeration budgets are reported.

## Execute and certify

Use `NumericJob.create` to pin worker command/dependencies, input artifact,
checkpoint, stage/time/memory budgets and stop rules before running. Its saved
checkpoints permit resume without changing the frozen job. Use the numeric
model APIs to explain convergence or prioritize a run, preserving their model
scope and holdout limitations. `score_bets` compares explicit portfolio costs
and supplied success-probability evidence while retaining a safe fallback.

Package a proposed numeric change through an ordinary project Line and call
`certify_numeric_bet(line)`. This runs the existing lab, build and full
verification sequence locally; it does not publish or submit anything. Report
actual artifact/certificate handles, measured resources, the unchanged host
objective, model assumptions and failed/unknown obligations separately.
