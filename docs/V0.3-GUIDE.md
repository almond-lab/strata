# Strata v0.3: the research loop

The connected agent originates optimization ideas. Strata recovers bounded
mathematical facts, executes constructors, checks candidates, prices emitted
circuits, and preserves evidence. `restructure` runs the installed constructors;
it does not call an AI service or invent unrestricted new algorithms by itself.

## From evidence to the next experiment

For fitting or quantization projects, begin with
[numeric candidates and pipelines](V0.3-NUMERIC-CANDIDATES.md),
[numeric studies](V0.3-NUMERIC-STUDIES.md),
[numeric models](V0.3-NUMERIC-MODELS.md), and
[checkpoint jobs](V0.3-NUMERIC-JOBS.md). These use the same artifact/evidence
discipline while treating the data that fills the circuit as the main object.
The circuit loop below is appropriate when emitted circuit structure dominates.

1. Run `strata discover circuit.kmx --out run/discovery`. Read the brief, exact
   functions, phase debts, repeated kernels, coverage and unknown spans. A
   repeated syntax kernel is a useful research target; it is not an arithmetic
   stage or permission to replace a fragment.
2. The agent proposes distinct mechanisms supported by those facts: consume an
   observable directly, change a representation, compress a dependent word,
   share bilinear products, or repay a measurement debt differently. Record the
   invariant, complete producer/consumer/return boundary, explicit assumptions,
   adaptation cost and decisive check. The user need not supply each idea.
3. Use `restructure` for the registered bounded constructions. For other ideas,
   the agent writes native candidate code or registers a trusted Python
   constructor through `ConstructorRegistry.register(name, propose, description)`.
   A proposal returns candidate text; it cannot change the acceptance checker.
4. Check exact full boundary behavior, including phase and restoration. If the
   task supplies a finite promise, run its separate domain check. Then run the
   unchanged host verifier and cost policy through the project workflow when
   available. A file check alone does not establish host acceptance.
5. Use concrete counterexamples and bounded/unsupported results to revise the
   construction. Retain valid alternatives even if they lose immediately: a
   later consumer change can make another representation useful. `restructure`
   archives states, attempts, a resource Pareto frontier, and a bounded next-round
   beam. The beam is not an exhaustive search.
6. Transfer verified native templates through the mechanism archive. Matching
   checks gate shape, wire renaming and clean-input predicates; every application
   is verified again. An old success, failed attempt or archive entry is not a
   proof about a new binding.

## A complete small example

Run from the installed Strata environment. Create `phase-word.kmx` containing:

```text
CCX q0 q1 q3
CZ q2 q3
CCX q0 q1 q3
```

With the explicit promise that `q3` starts at zero, this computes an AND word,
uses it in a phase, and restores it. The other three physical inputs are arbitrary.

```bash
strata discover phase-word.kmx --out run/discovery --clean-inputs 3
strata function-of phase-word.kmx --wire 3 --support 0,1 --at 1 --clean-inputs 3
strata slack phase-word.kmx --at 1 --clean-inputs 3
strata restructure phase-word.kmx --out run/search --clean-inputs 3 --rounds 2 --beam 4
```

The generic observable-phase constructor can emit `CCZ q0 q1 q2`. Its complete
receipt contains the emitted resource bill, exact sign/output check, bounded
independent concrete replay, and a layout mapping. In this example static
`Q*(toffoli+t/4)` changes from `4*2=8` to `3*1=3`. This is a fixture result under
the clean promise, not a measured host or competition score. Inspect
`run/search/restructure.json` and `run/search/best.kmx` for the actual run.

Reuse successful, rechecked templates on another supplied artifact with:

```bash
strata restructure another.kmx --out run/next --clean-inputs 3 --archive run/search/mechanisms.json
```

Declare that second circuit's real clean wires; the command above is appropriate
only when its `q3` is also guaranteed zero. Public input indices are fixed.
Removing an interior helper does not reduce emitted width if a higher public
wire still exists. Only declared, restored clean workspace may leave the layout.

## Finite promises and interior questions

A finite domain JSON file specifies complete boundary assignments. Register
integers are little endian in the declared physical wire order:

```json
{
  "version": 1,
  "type": "finite",
  "registers": {"inputs": [0, 1, 2], "helper": [3]},
  "assignments": [
    {"inputs": 0, "helper": 0}, {"inputs": 1, "helper": 0},
    {"inputs": 2, "helper": 0}, {"inputs": 3, "helper": 0},
    {"inputs": 4, "helper": 0}, {"inputs": 5, "helper": 0},
    {"inputs": 6, "helper": 0}, {"inputs": 7, "helper": 0}
  ]
}
```

Save it as `domain.json`. The standalone finite checker currently requires an
equal physical layout; it does not consume the constructor's clean-layout
mapping. For a separate finite check, save this equivalent retained-width
candidate as `phase-direct.kmx`:

```text
APPEND_TO_REGISTER q3 r0
REGISTER r0 "retained_boundary"
CCZ q0 q1 q2
```

Then check its complete boundary and query the original:

```bash
strata evaluate-file phase-word.kmx phase-direct.kmx --out run/domain-check --domain domain.json
strata function-of phase-word.kmx --wire 3 --support 0,1 --at 1 --domain domain.json
strata slack phase-word.kmx --at 1 --domain domain.json
strata floors phase-word.kmx --at 1 --domain domain.json
```

Rows may instead contain every `qN` bit. `union` can replace `assignments` with a
nonempty list of domain objects. Missing dirty inputs are errors; there is no
implicit zero fill. Classical inputs read by a window must also be explicit
`bN` bits. The normalized assignment set, register mapping, boundaries and hash
bind the result. Domain success remains separate from all-input equivalence.

`--from START --at STOP` selects `[START, STOP)` in canonical native **text line**
coordinates, including register metadata. The start is a new arbitrary boundary;
the prefix is not simulated. `--clean-inputs` or a domain then refers to that
boundary. A start inside an inherited condition scope is unsupported. For
example, `--from 1 --at 2` on the example asks about only `CZ q2 q3`; it cannot
infer the preceding AND relationship. File slack defaults to wires touched in
the chosen window; `--wires` selects an explicit larger set.

## Bounds and large inputs

Use `--max-operations`, `--max-variables`, `--max-terms` and
`--max-product-terms` to bound exact queries. Finite rows are bounded by
`--max-assignments`. Exhausted budgets return unknown; increasing a budget does
not change the promise. `function-of` also accepts `--timeout SECONDS`
(default 5), `--degree` (default 2, up to 3), and `--max-forms` (default 4096).
`slack` accepts `--timeout` (default 5) and `--max-inputs` (default 16) for
nonlinear distinct-state enumeration; affine rank uses its exact linear method.
These search clocks begin **after** the selected window's semantics are
available. Native loading, locating a deep window, and symbolic execution do
not consume the functional or slack search timeout.

Query receipts separate `load_seconds`, `window_semantics_seconds`, and
`search_seconds` for functional and slack queries, with `query_seconds` giving
the total query phase. An unsupported or over-budget window reports
`budget_phase: window_semantics`; search exhaustion reports `functional_search`
or `slack_search` and remains `unknown`. These are phase budgets, not an overall
process deadline. `floors` uses the shared operation, variable, term, product
and finite-assignment budgets above; its CLI computes derived bounds and does
not run the separate `exact_minimum` search. That Python API has its own
`timeout`, `max_and`, `max_states`, and `max_expansions` limits.

```bash
strata discover large.kmb --out run/range --range 10000:20000 --growth-window 4096
strata function-of large.kmb --wire 7 --support 0,1 --from 10000 --at 10100 --max-operations 100 --timeout 10
```

Discovery uses a native circuit plus a temporary text spool, bounded Python
windows, and a SQLite occurrence index. It reports elapsed time, peak RSS and
scope. It does not claim constant-memory native parsing or arbitrary full-file
symbolic synthesis. Recover a complete episode before constructing a replacement.

For `discover` and `inspect-file`, an explicit `--max-window` also sets the
streaming window cap unless `--growth-window` is supplied. With neither option,
the CLI keeps the 256-operation local proof window and 8192-operation streaming
cap. An explicit `--growth-window` controls streaming directly; the two caps are
not combined with `max`. In the Python APIs, `growth_window=None` uses
`max_window` as the streaming cap.
