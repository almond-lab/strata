# v0.4.1 verified comparisons and verifier draws

Issues #57 and #59 concern the scientific comparison contract, which is distinct
from the complete worker execution identity. Reports still retain every worker,
attempt, artifact and independent verifier receipt. A worker changing its script,
unused settings or output filename no longer creates a different cost comparison
group when the independent verifier and objective remain the same.

## Comparable independent evidence

New verifier receipts use `identity_schema: "strata-verifier/2"`. Their identity
pins the verifier declaration, executable/runtime identity, declared verifier
dependency bytes, referenced shared dependencies and inputs, explicit environment,
and every setting actually passed to the verifier. Declared draw values are
handled separately by the precommitted draw policy. Source filesystem locations,
worker-only dependencies, worker-only settings, output paths and inherited
execution limits do not define scientific comparison groups. Declare all files
the verifier loads, including imported helpers, as verifier dependencies; this
does not infer undeclared transitive imports or data dependencies.
Verifier execution stages only this declared closure. A helper declared solely
as a worker dependency is not silently available to a verifier sibling import;
declare it in `verifier.dependencies` as well when both commands need it.
The identity also pins dependency basenames and which declared files share a
staged sibling directory. Moving an entire verifier bundle preserves identity;
separating an imported helper from its verifier changes identity. Input and
dependency namespaces and independent directory roots remain distinct. Absolute
host directory prefixes do not affect this normalized layout identity.

An objective comparison additionally pins the formula, resource selectors, unit,
actual values of frozen formula constants, explicit scientific `contract`, and
declared compatibility metadata. Metric comparisons pin the verifier selector and
unit. Automatically generated manifest display names are not contracts. If two
manifests explicitly declare different contracts, they remain separate.

Reports validate the receipt identity and recompute each verified objective from
the verifier receipt before comparison. Legacy receipt identities remain readable;
legacy contracts are retained conservatively. Reporting needs only stored records
and blobs and does not rerun a worker or read its deleted source files.

`verified_baselines` contains the best eligible artifact in each semantic group.
`best_independently_accepted` exists only when the report has one comparison
contract. Its `reference` is the first complete accepted artifact in that group,
and `delta_from_reference` is the signed objective difference, not an independent
significance estimate. A baseline manifest and a separate candidate-producing
manifest can therefore establish an ordinary verified improvement.

## Precommit verifier draws

For a verifier invoked with `{setting:draw}`, a JSON manifest can declare:

```json
{
  "settings": {"draw": 101},
  "draw_settings": ["draw"],
  "draw_policy": {
    "aggregate": "mean",
    "draws": [{"draw": 101}, {"draw": 202}, {"draw": 303}]
  }
}
```

This fragment supplements the ordinary worker, artifact, verifier and objective
declarations. Every declared draw setting must be explicitly passed to the
verifier. The full finite draw set is frozen in the manifest **before execution**;
it is never inferred from whichever runs happen to finish or pass. A partial
sweep or a report scoped to a single draw cannot silently shrink that set.

The supported policies are:

| Aggregate | Acceptance and reported objective |
| --- | --- |
| `mean` | Every draw must pass; arithmetic mean of independently verified per-draw objectives |
| `worst` | Every draw must pass; largest objective for minimization, smallest for maximization |
| `all` | Every draw must pass; retain the complete draw vector without declaring a scalar ranking |

The cost formula is applied **before** averaging. For example, resources 2 and 4
with cost `work**2` produce mean cost 10, rather than 9 from squaring the mean
resource or 4 from selecting the cheapest draw. These are finite-draw empirical
comparisons, not exact population expectations or statistical confidence bounds.
The existing project `ProbabilityPolicy` remains unchanged and continues to
provide its own precommitted-draw and failure-budget checks.

When the verifier consumes `{seed}`, declare `draw_policy.seeds`, a nonempty list
of distinct integer seeds. `draw_policy.replicates`, a positive count defaulting
to 1, commits replicate indices `0` through `replicates - 1`. The expected slots
are the Cartesian product of draw rows, declared verifier seeds and replicates.
Worker search seeds do not become verifier draw dimensions unless explicitly
declared in the policy. Declared seeds and repeats must be matched for every
artifact; an incomplete repeat set is ineligible. Each policy is capped at
100,000 expected slots.

## Artifact grouping and conservative exclusions

`artifact_comparisons` appears in both reports and agent packets. It groups the
hashes of the actual artifacts passed to the verifier, in their argument roles,
with the semantic verifier/objective identity. It retains individual observations,
expected and missing draws, the declared aggregate and exclusion reasons.
Changing an artifact's filename does not change its byte identity. Other outputs
which were not passed to the verifier do not split an otherwise identical artifact.

An artifact is eligible only if every expected slot has verified acceptance and
an independently verified objective. A rejected draw, missing result, unexpected
draw or conflicting repeated observation withholds its aggregate. Repeating the
same artifact/draw through another producing manifest does not add extra weight:
agreeing duplicate receipts are retained and counted once. A duplicate rejection
or different objective blocks the group rather than selecting the favorable retry.

Two artifacts are ranked together only under identical complete draw policies
and objective contracts. Different draw sets produce separate groups and no
cross-group best. A single artifact which changes bytes across the draws does
not establish a complete fixed-artifact comparison.

Without a declared policy, settings and seeds passed to the verifier remain part
of its comparison identity. If retained experiment plans vary those verifier
conditions, reports conservatively withhold scalar baselines rather than choosing
a lucky or early draw, even while some planned runs are unfinished. Repeated
independent checks of identical artifact bytes must also agree. Worker-only
settings remain ordinary candidate search parameters. Hidden verifier randomness
cannot be discovered automatically; stochastic verifiers must declare their draw
inputs and policy.
Native source-setting transfer suggestions currently abstain for verifier-varying
or declared draw-policy manifests. Their individual draw improvements cannot
stand in for a complete artifact comparison; the full aggregate evidence remains
in the report.

## Regression evidence

`tests/test_v041_comparisons.py` covers cross-manifest actual execution and
store-only regeneration, verifier/dependency/objective/constant/unit/contract
separation, nonlinear means, direction-aware worst draws, vector-only all draws,
failed and incomplete sweeps, mismatched commitments, duplicate artifacts and
draws, pending undeclared sweeps, seeds and replicate completeness, and malformed
or mutated declarations. Setting `STRATA_REAL_SANDBOX=1` runs the cross-manifest
execution case through the actual offline Bubblewrap runner instead of the test
transport. These checks establish comparison bookkeeping behavior; they do not
certify arbitrary verifier mathematics or historical competition acceptance.
