# v0.4 experiment workflow

The generic experiment layer wraps existing numeric, circuit-generator and
simulation scripts. It executes declared work and returns retained evidence to a
connected agent. The earlier circuit analysis/construction APIs remain available;
this layer does not claim to solve their open semantic-lifting milestones.

Start with [the ten-minute guide](TEN-MINUTES.md). The original
[v0.4 plan](V0.4-PLAN.md) describes the motivation and acceptance questions.

## Manifest and identity

A JSON or TOML manifest contains an `argv` array or a list of named `stages`,
`settings`, named `inputs`/`dependencies`, explicit `environment`, `resources`,
per-stage `limits`, total `max_wall_seconds`, and `max_attempts`. The runtime,
declared files, reader implementation and nonsecret environment are frozen.
Dependency directories are supported. Automatic pinning cannot discover every
undeclared external file or transitive library: declare the source and data your
experiment actually depends on.

Arguments use exact `{setting:name}`, `{input:name}`, `{dependency:name}`,
`{artifact:name}`, `{seed}`, `{replicate}`, `{workdir}` or `{checkpoint}`
placeholders. Substitution never evaluates shell text. Working inputs are staged
inside a fresh attempt directory. Output paths must be relative and may not
escape through traversal or symlinks.

Since v0.4.1, staged files retain their original basename and extension. Files
declared from the same source directory are staged together, so a Python script
can import its declared sibling helpers. Unrelated source directories stay
separate; use a declared package directory for package-relative imports. Artifact
and checkpoint placeholders also preserve the declared filename. Depend on the
placeholders, not the private `.strata` staging layout.

Each output declares `name`, `path`, and `type` (`json`, `jsonl`, `csv`, `text`
or `binary`), with an optional supported JSON-schema subset. Metric declarations
select a value from a named output with a dotted path, JSON pointer or path list,
plus an explicit unit and evidence kind. CSV and JSONL arrays can select their
`last` row. Missing metrics remain missing, never zero. Logs are retained even
when an attempt fails.

Empty UTF-8 `text` and `jsonl` outputs are valid by default. Set `nonempty: true`
to require content. Binary outputs default to nonempty; `nonempty: false` allows
an explicitly empty binary. JSON and CSV must still decode as valid JSON or a
CSV with a unique header, even when `nonempty: false`. Missing files and missing
metric selectors still fail. `nonempty` must be a boolean.

## Disk retention

The default `retention: compact` removes private staging files and successfully
validated stage outputs once identical bytes have been verified in the immutable
object store. All receipts, logs, artifacts and committed checkpoints remain
accessible by their stored handles; resume restores them from those objects.
Changed, incomplete or unvalidated worker outputs remain for diagnosis. Cleanup
errors are reported separately and do not erase the run result. `retention: keep`
retains attempt files for manual inspection. Retention only touches the current
owned attempt; it does not sweep old or other agents' work directories.

Restoration uses private copy-on-write reflinks where supported and a streaming
copy elsewhere. It never hard-links writable worker outputs to immutable objects.
On a filesystem without reflinks, a one-stage worker plus verifier can temporarily
hold four attempt copies of a large unchanged input (input, output, verifier
input and verifier artifact), plus its object-store copy. Compact retention drops
these duplicate retained bytes after the attempt; it does not eliminate transient
peak storage. `storage_bytes` is a cooperative working-storage reservation, not
a disk quota or a bound on the global object store. Reserve enough for that
temporary peak and the script's own files. The finish receipt reports removed
logical bytes; this is not a measurement of physical blocks freed on a reflink
filesystem.

The complete runnable examples are:

| Task family | Manifest | Independent check |
| --- | --- | --- |
| Numeric fitting | [`numeric.toml`](../examples/workflow/numeric.toml) | Recompute predictions and mean squared error from the fixed data |
| Circuit generation | [`circuit.json`](../examples/workflow/circuit.json) | Exhaustive parity contract at the declared width, including dirty target restoration behavior |
| Non-contest data processing | [`words.json`](../examples/workflow/words.json) | Independently tokenize and count the frozen input |

These are generic reference fixtures. An official contest verifier is an
explicit user-supplied plugin command, not a bundled replacement or a hardcoded
contest formula. A verifier needs an explicit version/source and pinned
dependencies, receives the actual candidate artifact, and emits a structured
receipt with a boolean acceptance selector. Strata retains that receipt and
checks that verification did not modify the candidate.

The verifier receives its own declared dependencies and inputs explicitly
referenced by its command. Declare its imported helper files in
`verifier.dependencies`; unrelated worker dependencies are not exposed to it.
This makes the bytes used for verification agree with its comparison identity.
Changing a verifier helper, objective, frozen constant or explicit contract
separates comparisons; changing only the candidate-producing worker need not.
For stochastic verification, precommit the draw set and aggregation before
running. See [draw-matched comparisons](V0.4.1-COMPARISONS.md).

Cost formulas are declared in the manifest. Bind variable names through
`cost.resources` to selectors in the independent verifier's JSON receipt;
declared frozen settings can supply constants. Worker metrics alone cannot
establish a verified cost. Discontinuities such as `ceil` and `floor` belong in
the exact supplied formula and are not smoothed away by the scheduler.

## Experiments, attempts and sweeps

`create_experiment` freezes a configuration identity. Repeating that creation
finds the same experiment. Seeds and explicit replicates distinguish intentional
repetitions; retries create separate attempts. Changed settings or budgets create
a new experiment, optionally with an explicit parent:

```bash
strata experiment create pipeline.json --store work --parent PREVIOUS_EXPERIMENT
strata experiment run EXPERIMENT_HANDLE --store work --owner agent-a
strata experiment status EXPERIMENT_HANDLE --store work
```

`create_sweep` accepts explicit parameter dictionaries or a Cartesian grid,
distinct seeds, a replicate count, a maximum job count and worker concurrency.
Cardinality is checked before materializing large grids. Each worker uses its own
Store connection and participates in the same resource board. Current scope is
one Linux host. A larger worker count cannot bypass the shared reservation pool.

An unfinished attempt is conservatively charged its reserved budget and requires
reconciliation. A policy pause does not reset attempts or wall-time accounting.
Report wall time separately from CPU time and peak memory; unavailable resource
measurements remain null.

## Checkpoints and safe cancellation

Declare a checkpoint path, format and schema at a stage boundary. A completed
stage's valid checkpoint is retained. Recovery from a failed stage additionally
requires a declared commit marker binding the checkpoint bytes; mere file
existence cannot establish a committed checkpoint. Set `checkpoint.commit_marker` to a relative text
file containing the exact lowercase SHA-256 digest of the current checkpoint.
The marker must be written only after the checkpoint bytes are committed.
Declare `resume_argv` when the script supports resuming from that checkpoint.
Otherwise a failed stage can be
restarted, but Strata cannot manufacture mid-stage continuation.

Completed stage reuse must match the upstream artifact lineage. Rerunning an
earlier stage with new bytes invalidates downstream reuse. Source/runtime/reader
drift blocks resume; use an explicit descendant experiment for a changed method.

```bash
strata board --store work
strata board --store work --cancel JOB_ID
strata board --store work --events-after LAST_SEQUENCE
strata board --store work --reconcile JOB_ID
```

Cancellation is a request to the owning supervisor. Only that owner stops its
identified sandbox. No process-name matching or guessed PID is used. Expired
leases retain reservations until ownership is reconciled; expiry alone cannot
kill work or start a duplicate. Process identity includes Linux boot/start-time
information. The supervisor is the owning local worker with durable records, not
an independently installed background daemon. An absent owner is reported and
must be reconciled.

Execution uses the offline bubblewrap boundary. There is no unsandboxed fallback.
`experiment run` keeps its JSON receipt and returns exit code 1 for failed,
rejected, paused or otherwise incomplete runs; malformed requests return 2.
Exit code 0 still requires reading the status: execution or artifact validation
without an independent verifier is not accepted scientific evidence.
Reservations are cooperative; process address-space/CPU/file limits are distinct
from aggregate quotas. Hard aggregate requests require a different backend and
are rejected by this one. A signal alone cannot prove an OOM event. Failure
reports preserve the actual exit/signal, diagnostics and bounded stdout/stderr.

## Calibrated cheap gates

`ScreeningPolicy` takes a frozen identity containing scorer, dependencies, domain,
settings and unit; proxy/full thresholds; calibration requirements; a maximum
false-negative rate; and a deterministic full-evaluation audit fraction.
Calibration records contain actual paired cheap/full receipts with disjoint
training and held-out candidates. Both sets need failures, successes and boundary
cases. Receipt/value/unit binding and overlap checks prevent reusing a proxy as
its own full verification evidence.

The policy reports a one-sided binomial upper bound under its declared
independent, representative-sample assumption. Insufficient evidence, changed
identity or an unsupported domain yields abstention. Audit-selected candidates
continue through full evaluation even when the cheap gate rejects them. Retain
their false-negative results; screening is a model decision, never a proof of
impossibility or an acceptance result.

Derive the identity from the actual manifest before collecting calibration.
Save this as `identity-request.json`, using your manifest path and metric name:

```json
{"operation":"evaluator_identity","manifest":"pipeline.json","metric":"loss"}
```

```bash
strata experiment-policy identity-request.json --store work
```

The response contains an `identity` object and a retained `record` handle.
Optional `settings` overrides must match the settings used by the experiment.
The identity binds actual stage commands, reader, runtime, environment, declared
dependency bytes, verifier and cost settings. Adding a policy declaration does
not change that evaluator identity. Pipeline execution derives it again; copying
an old identity into a changed manifest cannot make stale calibration valid.

Put the returned handle in place of `IDENTITY_RECORD` in `gate-request.json`:

```json
{
  "operation": "create_screening",
  "identity": "IDENTITY_RECORD",
  "proxy_threshold": 1.0,
  "full_threshold": 1.0,
  "boundary_margin": 0.05,
  "max_false_negative_rate": 0.05,
  "audit_fraction": 0.1
}
```

```bash
strata experiment-policy gate-request.json --store work
```

This creates a declaration; pruning remains disabled until calibration passes.
JSON operations `record_candidate` and `record_pair` bind proxy/full metric
values to retained source receipts. `calibrate` takes the returned `policy` handle
and disjoint `training` and `heldout` lists of pair handles. `decide` and `audit`
retain their decision and full-evaluation evidence. The Python equivalents are
`experiments.evaluator_identity`, `ScreeningPolicy.create`,
`record_screening_candidate`, `record_screening_pair`, and the policy's
`calibrate`, `decide`, and `audit` methods.

A manifest's `screening` field supplies `policy`, `calibration`, the derived
`identity` object, `metric`, and `after_stage` cheap-stage boundary. Optional
`full_stage` and `full_metric` identify the paired full evaluator; defaults are
the last stage and the same metric. The pipeline applies the decision before
the expensive stage and retains full-evaluator audit results. A new audited
false negative suspends further pruning until recalibration includes it. Every
candidate still needs independent full verification before promotion.

## Continuation policies

`ContinuationPolicy` models the decision to continue this particular live run
until a declared absolute stage horizon. It is separate from the earlier
independent-run convergence forecast. The initial model compares measured
trajectory prefixes, with an explicit distance scale and minimum neighbor count.
Its predicted probability is an empirical model estimate, not a calibrated
probability certificate.

Stage numbers are one-based positions in the frozen pipeline. Only stages with
retained checkpoints contribute live trajectory points; a stage without a
checkpoint still occupies its stage number. Resume preserves these positions.
Use the same stage numbers in calibration trajectories. `min_evidence` counts
measured checkpoint points, while `horizon` and `cadence` use stage numbers.
The JSON operations are `create_continuation`, `record_trajectory`, `calibrate`
and `decide`; the Python equivalents are `ContinuationPolicy.create`,
`record_trajectory`, and the policy's `calibrate` and `decide` methods.

Freeze the horizon, cadence, minimum evidence, model parameters, acceptable
lost-win risk and whether automation is enabled. Validate on disjoint whole
trajectories through the measured horizon, including plateau-then-late-win
examples. Calibration reports proposed stops, lost wins, risk bounds and
retrospective compute savings. Unsupported prefixes abstain. Advisory mode is
the default.

An enabled, sufficiently validated policy may pause only at a retained checkpoint
boundary. It creates `paused_by_forecast_policy`, preserving the checkpoint and
charged budget. Resume explicitly:

```bash
strata experiment run EXPERIMENT_HANDLE --store work --override-policy
```

The override is recorded and grants no new budget. A failed search or an early
pause must not become a permanent structural impossibility claim. Keep its
scope and reopening condition in the research packet.

## Reports and the connected-agent loop

```bash
strata experiment-report --store work --format markdown --out work/report.md
strata agent-packet --store work --out work/packet.json
strata agent-decision decision.json --store work
```

Reports reconstruct from retained receipts. They distinguish compatible verified
baselines from modelled bets, show missing metrics explicitly, and can incorporate
the existing error-budget ledger, design-space evidence and portfolio formula.
Signed cross terms remain explicit in error accounting. Task-specific parameters
such as lambda are supplied as named evidence, not library constants.

An agent packet contains active ownership, prior experiments, failures,
uncertainties, verified comparisons and prior agent decisions. Native manifest
experiments can propose sibling-line transfers directly: declare `line`,
`contract`, and `compatibility` with `shape`, `units`, `parameter_meanings` and
`dependencies`. Save `{"transfer_experiment":"TARGET_EXPERIMENT","metric":"loss"}`
as `transfer.json`, then run `strata agent-packet --store work --payload transfer.json`.
Selecting `--experiment TARGET_EXPERIMENT` also enables this path when that
manifest declares compatibility. No `NumericStudy` adapter is required; existing
`NumericStudy` transfers remain available through `transfer_target`.

Suggestions require a source improvement over an independently accepted source
baseline, verified objective values, identical setting names, compatible declared
meaning and matching actual code/verifier/runtime/reader/environment identities.
Settings already attempted on the target line are excluded. Input hashes must
also match by default. For intentionally different sibling data blocks, both
manifests may declare the same `compatibility.transfer_inputs` list of input names.
Their contents may then differ; the packet records both input hashes and the
changed names. Source improvements are compared on identical source inputs.
Every suggestion retains source and target identities and remains a hypothesis:
different target data never inherits the source's verified gain.

Packets default to 32 transfer suggestions and 50 entries per history/comparison
list. Payload fields `transfer_limit` and `packet_limit` accept integers from 1
through 256. Counts and truncation flags accompany these lists; active jobs remain
visible, and the retained `report` handle links to complete outcomes and agent
decisions.

The agent's decision JSON names the retained `packet`, `hypothesis`, newly
created `decisive_experiment`, `expected_outcome`, positive named `budget`,
`reopening_condition`, and optional `actor`. Strata binds the decision to its
evidence. Run that experiment and generate the next packet: its outcome and the
preceding hypothesis are then visible together. A CLI invocation does not itself
call an AI service; the connected agent supplies the reasoning step.

Decisive-test manifests declare the question, frozen settings, relaxations, their
mapping to the real contract, threshold and interpretation. Success on a relaxed
task motivates a full candidate. Incomplete optimization failure cannot establish
that the full task is impossible.

The release's test and benchmark receipts distinguish fixture measurements from
production claims. A fast sweep of small scripts does not establish throughput
for millions of full circuit simulations or prove a contest score improvement.
