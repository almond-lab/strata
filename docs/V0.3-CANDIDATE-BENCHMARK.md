# Candidate-search benchmark

This experiment actually screened **2,000,000 distinct algebraic decomposition specifications** by exact tensor coefficients. It also made **28 native finalist replays**, covering **26 distinct native programs**, **7,168 exhaustive input shots**, and **28 final symbolic equivalence checks**. Those are separate quantities: this report does not claim two million native programs or certified replacements.

The retained machine-readable result is [candidate-search-million.json](benchmarks/candidate-search-million.json). A separate [native pipeline benchmark](V0.3-NATIVE-CANDIDATE-BENCHMARK.json) actually built and simulated **1,000,000 distinct native circuits** in **595.85 seconds**, checking **256,000,000 input trajectories**. That throughput experiment is different from this analysis-guided search; its timings must not be replaced with the algebraic screen's throughput.

## Measured results

| Case | Proposal strategy | Complete specifications screened | Exact coefficient survivors | Unique programs materialized | Native finalist replays | Native input shots | Total seconds | Best emitted Q × Toffoli |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| development | random | 1,000,000 | 4 | 4 | 4 | 1,024 | 0.453 | 56 → 40 |
| development | guided | 63 | 63 | 63 | 8 | 2,048 | 0.091 | 56 → 36 |
| held_out_partition | random | 1,000,000 | 22 | 22 | 8 | 2,048 | 0.379 | 48 → 36 |
| held_out_partition | guided | 311 | 311 | 128 | 8 | 2,048 | 0.191 | 48 → 36 |

The development instance has a 3 × 3 × 2 tensor, 147 rank-one atoms, and 18,671,940 possible unordered four-product specifications. The held-out instance changes the input partition to 2 × 4 × 2: 135 atoms and 13,232,835 specifications. Neither route searches arbitrary circuits. These timings are single local runs, not confidence intervals or hardware-independent throughput promises.

Unguided sampling uses a fixed seed and uniform sampling without replacement. Guided search constructs 10,731 and 9,045 pair records, respectively, then solves the remaining tensor residual by matching pair coefficients. It visits 189 and 933 matching pair combinations and removes duplicate four-product sets before exact screening. This exhausts the guided identity search at 63 and 311 complete equivalent specifications; it does not manufacture a million proposals after exhaustion.

The random route finds 4/1,000,000 and 22/1,000,000 exact identities. The guided proposal fraction is 63/63 and 311/311 because residual matching deliberately solves the coefficient equation. That fraction measures proposal precision, not unbiased success probability or learned prediction quality. On these instances, the restricted algebraic solver uses less total measured time and finds a better priced development result; the held-out best objective ties. Equal candidate caps do not mean equal computation, and this is not a controlled equal-wall-time comparison.

## What was searched and checked

The reusable implementation is [candidate_search.py](../src/strata/candidate_search.py). Every candidate is an unordered set of four **different** rank-one products of a left-linear form, a right-linear form, and an output mask. Sorted atom identifiers give an injective combinadic identity. Permutations of the same products and repeated-product cancellations do not inflate the candidate count. Different complete specifications can still compute the same function; finding multiple realizations of the target function is the search objective.

Each benchmark source is emitted as native coordinate-product code and then analyzed with `analyze_window`. The recovered bilinear partition and deltas determine the tensor. The generator's short decomposition is discarded and unavailable to search. Tensor floors are computed in their stated bilinear model; a proved floor above four rejects this search family. This floor is not a general reversible-circuit, measurement, or task-cost lower bound.

Both strategies have the same four-product family, candidate cap, materialization cap of 128, native replay cap of eight, and emitted `Q*toffoli` objective. All coefficient-survivor counts are recorded before these caps. At most 128 survivors in canonical specification order are materialized, and the best priced eight among those are selected for native replay. The held-out guided run therefore does not claim to have priced every one of its 311 identities.

Materialized programs are parsed by kickmix, hashed in canonical native form, and checked for duplicates. Their quantum width includes any clean helper actually used: the baseline uses eight physical wires, and finalists may require nine or ten. Two explicitly zero helper inputs are available equally to both routes. There is no unpriced arbitrary ancilla or dropped dirty output.

Native replay uses a selector-controlled batch: each shot enables exactly one finalist program, and every finalist receives all 256 assignments of its six public inputs and two dirty output accumulators. The SDK checks all physical outputs, helper restoration, and the exact sign. There are zero forced measurement events in this family. Every passing finalist is then independently compared with the reference using exact symbolic ANF and sign semantics under the same explicit clean-input promise. A seeded test injects a phase error after coefficient screening and verifies that native/final verification rejects it.

The held-out case is a separate tensor partition and independently fixed instance seed. This tests transfer of the same algebraic algorithm to a different bounded family member. It is not evidence of model training, unrestricted architecture discovery, or host-task acceptance.

## Reproduce

```bash
.venv/bin/python scripts/benchmark_candidate_search.py \
  --candidates 1000000 \
  --out docs/benchmarks/candidate-search-million.json
.venv/bin/pytest tests/test_candidate_benchmark_v03.py -q
```

The report stores both recovered tensors, source circuits, seeds, native finalists, artifact hashes, partial-search work, stage timings, Python/NumPy/kickmix versions, platform, peak RSS, and exact implementation/script hashes. Sampling a million indices uses bounded benchmark-sized arrays; this experiment is separate from the constant-window file-scanning path.
