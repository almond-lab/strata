## Regression evidence

- `test_lab_issues.py` and `test_lab_audit.py`: exact native cross-checks,
  promised input scope, nonlinear combined-branch failures, reset legality,
  deterministic shards and component receipts.
- `test_task_issues.py`: config-only bundles, numeric changes, frozen components,
  dependency pins, typed callbacks and scaled component labs. Its default
  transport executes the real fixture verifier but replaces the namespace
  boundary. The release separately passed the config-only full-pipeline test with
  `STRATA_REAL_SANDBOX=1` (1 test, 5.36 seconds); other test-transport cases
  are not individually relabeled as sandbox runs.
- `test_memory_issues.py` and `test_reports_issues.py`: stable hashes, conservative
  evidence, real local formats, changed-base scope, source-independent reports,
  failed/successful/nonbuilt outcomes and prebuild notes.
- `test_inference_issues.py`, `test_floors_issues.py`,
  `test_probability_issues.py`, and `test_frontend_issues.py`: bounded witnesses,
  exact-small or unknown floors, precommitted draws and codec equivalence.

See [the acceptance ledger](ACCEPTANCE.md) for historical R1–R6 limitations and
actual log counts. Private source bodies are not part of this release evidence.

Additional release regressions: `test_probability_project.py` checks nonlinear
per-draw pricing through a complete Line and replay, plus rejection of favorable
draw selection. `test_fresh_discovery_acceptance.py` checks the no-hypothesis
original-file trial; it does not use a historical competition case.

`test_region_evidence.py` adds six source-less evidence regressions: retained-byte
replay after deleting the source, raw operation input, explicit unknown
measurement/condition contexts, certificate links, and rejection of forged
phase, boundary, assumptions and source identities. Together with existing
file-workflow/discovery tests, the focused run passed 30 tests.
