# v0.4 plan: a working experiment loop for existing research pipelines

**Original design plan.** See [the v0.4 workflow guide](V0.4-WORKFLOW.md) for the
implementation and its limits; individual acceptance claims require validation
receipts. This plan incorporates
the team's time breakdown supplied on 17 November 2026. It is separate from the
[v0.3.1 fixes](V0.3.1-FIXES.md). The breakdown is evidence from one team, not a
benchmark of Strata or a promise of time saved.

The goal is to shorten the path from an existing script and a research question
to an informative, reproducible experiment. Strata should launch the work,
account for resources, collect useful evidence and return structured insights to
the connected agent. The agent should use that evidence to propose the next
structural hypothesis. Bookkeeping alone does not meet this goal.

Two parallel needs remain: improve circuit understanding and construction, and
make numeric/generator experiments practical to run. This plan addresses the
second without substituting it for the first. Open circuit research issues
[#48](https://github.com/almond-lab/strata/issues/48),
[#49](https://github.com/almond-lab/strata/issues/49) and
[#50](https://github.com/almond-lab/strata/issues/50) remain separate work.

## What the time breakdown changes

| Observed work | v0.4 response | How to measure whether it helps |
| --- | --- | --- |
| Reading/onboarding: 1 h; writing tools: 4.5 h | Wrap an existing command without a Python adapter; a ten-minute first-run guide | Time to first retained, checked result; integration code and manual steps required |
| Running experiments: 10.5 h, reported as 47% | Declarative bounded sweeps, calibrated screening and early decisive experiments | Operator interventions, total compute, time to informative results, missed valid candidates |
| Coordination: 0.8 h; waiting: 1.5 h; reading: 1 h | Shared claims, resource reservations, completion events and session digests | Duplicate launches, idle wait time, missed results and redundant experiments |
| Debugging: 0.9 h | Owned process supervision, failure evidence and validated artifacts | Diagnosis time; unintended process termination; false successful completions |
| Analysis: 2.4 h | Standard error, cost, shape and comparison reports | Time to answer the next decision; agreement with independent reference calculations |

Do not add these categories into an asserted independent saving: activities may
overlap, and compute time is not the same as time requiring human or agent
attention. Measure both in the acceptance study.

## 1. First useful result without a task adapter

Add a command wrapper around the team's current fit, round, build or simulation
script. A small manifest declares argv (as an array), working directory, inputs,
settings, dependencies, resource limits, output files and metric selectors.
Provide JSON, JSONL and CSV readers for files the script already writes. Capture
stdout/stderr even when no machine-readable metrics are available; in that case
report that numeric analysis is unavailable instead of inventing a score.

The wrapper records input/code/configuration identities, each attempted command,
settings, timestamps, outputs and checkpoints. It does not require the user to
define a circuit tree, Bloq or custom Python adapter to record and run a job.
Record executable/runtime identity, explicit nonsecret environment and thread
settings, and the output-reader schema version. A changed dependency, runtime,
reader or relevant environment must invalidate result reuse and affected
calibration. Source pinning alone does not freeze every transitive library.
A script that already supports checkpoints can declare how to resume. Otherwise
Strata can restart a stage, but cannot promise mid-stage continuation.

Make the first guide a single page: install, wrap an existing command, run two
settings, inspect the result and resume an interrupted job. Every command in
that guide must run in CI. Detailed developer documentation remains separate.

Use optional, versioned starter plugins for recurring task families. A plugin
may supply a pinned official verifier, exact cost formula, artifact schema and
reference examples when available and legally distributable. Generic core APIs
must also work with a user-supplied executable verifier. No contest names,
table sizes, lambda constants or scoring weights belong in the core scheduler.
Pin the verifier version and record its source; never silently fetch or update
the acceptance criterion during an experiment.

**Acceptance:** two unrelated existing scripts, one numeric and one circuit
generator, run unchanged from manifests without Python adapter code. A third
non-contest workload demonstrates that the interface is generic. A new user can
reach a checked example result within ten minutes in the documented reference
environment; report the measured setup time rather than extrapolating it to all
external pipelines.

## 2. Execute a declared experiment, not twenty hand-written commands

A frozen sweep specification declares parameter sets/ranges, seeds, input hashes,
pipeline ordering, concurrency, aggregate reservations and per-attempt budgets.
Keep planned experiments distinct from execution attempts: retries share a
configuration identity but retain separate failures, logs and resource charges.
An explicit repeat/seed field allows intentional replication. Do not deduplicate
stochastic replicates merely because their settings match.

The coordinator launches eligible jobs, collects metrics and compares compatible
results. Interruption/resume must preserve the experiment plan and reuse only
validated completed outputs with matching dependencies. Readiness is a trigger
for packaging and independent verification; it is not itself acceptance.

### Cheap gate before an expensive run

Let teams register a cheap evaluator and a full evaluator over the same declared
candidate contract. Retain a calibration set containing failures, successes and
cases near the acceptance boundary. Bind calibration to evaluator versions,
dependencies, domain and settings. Audit a sample of rejected candidates with the
full evaluator to estimate false negatives; otherwise the screening policy can
appear perfect while missing every interesting candidate.

A cheap metric remains model evidence. Before calibration, use it for ranking or
advice. An enabled pruning policy declares its tolerable false-negative risk and
abstains outside its calibrated domain. Never label a screened-out candidate
mathematically impossible or update the retained verified best from the proxy.

### Decisive experiments before long optimization

Offer a template that freezes all but the suspected bottleneck and optionally
relaxes the rest. Require an explicit mapping from each relaxation to the real
contract, the question being tested, and its predicted resource/error threshold.
The connected agent proposes the relaxation; Strata packages the experiment and
records what the result actually establishes.

A relaxed success only motivates a full candidate. A relaxed failure from an
incomplete optimizer is not an impossibility proof. Only a justified lower bound
or complete search over a declared domain can close that domain. Keep an
obstruction's scope and reopening condition in the session digest so an old
heuristic failure does not become a permanent ban on a structural idea.

### Trend-based stopping, with the correct prediction target

Current `forecast_convergence` estimates an outcome for a new independent run
from a declared population. It does not establish the probability that a
particular live run will succeed if continued. Its held-out endpoint diagnostic
does not calibrate future extrapolation. Current observed stop rules intentionally
do not accept forecasts as measured evidence.

Keep forecasts advisory by default. An opt-in continuation policy must declare
its model identity, training evidence, decision target, horizon, minimum evidence,
decision cadence, thresholds and pruning risk before execution. Validate on
held-out *trajectories*, including plateaus followed by improvements, and abstain
when the model is unsupported. Record compute saved, false pruning and lost wins.

A forecast stop creates a resumable `paused_by_forecast_policy` state, retaining
checkpoints and the decision receipt. It never means proof of failure, successful
completion or permission to replace the safe candidate. Successful promotion
still needs a real artifact and independent verification.
Resume preserves the original charged compute budget and records overrides.
Changing an immutable policy or extending a budget creates an explicit descendant
job; it must not silently reopen a terminal job with fresh uncharged resources.

**Acceptance:** the declared twenty-setting fixture requires no per-setting
commands; pause/resume preserves all planned replicates. A cheap-gate benchmark
reports full-evaluator savings and missed accepted candidates against evaluating
every candidate. Forecast automation is withheld if its continuation calibration
does not meet the declared risk threshold.

## 3. One experiment board for people and agents

Build a shared board over retained records rather than a second research store.
Use transactional job claims and leases, resource reservations and ordered events.
The initial scope is participating workers on one Linux host, suitable for the
shared VM. Do not imply a distributed cluster scheduler.

Claims include the experiment, attempt, owner, requested threads/memory/storage,
granted slots, heartbeat and lease. Expiry permits investigation/reconciliation;
it must not automatically kill an unidentified process or start a duplicate while
the original may still be running. An agent can work on another task and consume
completion events from a saved cursor. CLI and agent-tool notifications need no
email, Slack or other external messaging.

At session start, generate a deterministic digest: retained verified best,
active jobs and owners, completed comparisons, failed hypotheses with evidence
and reopening conditions, unresolved questions, and compatible settings not yet
tested in sibling lines. Link every claim to its run/artifact. Avoid rescanning
every large artifact to refresh the board; maintain indexed projections that can
be rebuilt from the retained records.

Recombination prompts must check contract, parameter meaning, units, shape and
dependencies. A setting that worked elsewhere is a proposed experiment, not an
assumed transferable win. The connected agent receives a compact structured
packet and chooses a hypothesis, decisive test and bounded next experiment. Its
response is retained so the next iteration can connect decisions to outcomes.

**Acceptance:** simultaneous workers cannot claim the same attempt or overspend
the cooperative reservation pool; replayed events do not duplicate completion.
Lost workers reconcile without unsafe cancellation. A compatible verified win
generates an untested sibling suggestion, while an incompatible shape is rejected
with a reason. A new agent can reconstruct the state from the digest alone.

## 4. Process ownership and honest completion states

Add a persistent local supervisor with attempt identity, owner token, process
identity/start time, process group and optional delegated cgroup. Cancellation
must act only on the owned process set; never use process-name matching or a PID
without validating its identity. A missing supervisor is a distinct state to
reconcile, not automatic evidence that the work stopped safely.

Keep cooperative CPU reservations distinct from enforced limits. Report requested
threads, granted slots, effective affinity and actual usage separately. Existing
`RLIMIT_AS`, `RLIMIT_CPU` and `RLIMIT_FSIZE` are not aggregate descendant-memory,
worker-pool CPU or total-disk quotas. Use cgroups or another declared enforcement
mechanism for hard aggregate limits. If a requested hard guarantee is unavailable,
fail before launch or require the manifest to explicitly choose cooperative
limits; do not silently downgrade it.

Retain exit status, signal, stderr, resource evidence and last committed
checkpoint. Report OOM only with supporting evidence such as an owned cgroup's
OOM event. `SIGKILL` alone is an unknown external/resource kill. Library-crash
classification must cite the actual diagnostic rather than infer a root cause
from a missing result.

Separate `execution_finished`, `artifact_validated` and `accepted_by_verifier`.
Exit code zero is insufficient. An output must exist, be a new artifact of this
attempt rather than a stale file, match its schema and declared checks, and have
its bytes hashed. Retain packaging/check failures. Local verification does not
submit or publish a candidate externally.

**Acceptance:** test grandchildren, timeouts, supervisor death, stale PIDs,
partial outputs, stale artifacts and zero-exit/no-output scripts. Cancelling one
job leaves an unrelated sentinel job alive. Resume preserves the last committed
checkpoint; no failed or unverified artifact replaces the safe candidate.

## 5. Reports that answer the next research question

Generate JSON and readable views from the same receipts:

- Error budget by named source, stage and structure, with units and evidence
  kind. Support cross terms/interactions explicitly; do not force a nonadditive
  error into a misleading additive chart.
- Resource and cost accounting, including exact shape-dependent discontinuities,
  named multiplicative factors, break-even values and permitted error budgets.
  Formulas come from the pinned task/plugin, including any parameter called lambda.
- Per-candidate comparisons with the verified safe baseline, unsuccessful
  mechanisms, remaining uncertainty and concrete next experiments.
- Run curves, resources, checkpoints, gate decisions and failure diagnoses.
  Forecasts carry model version, calibration scope and uncertainty.
- Portfolio comparisons only under the declared portfolio formula. Modelled bets
  and independently verified candidates remain visibly separate.

**Acceptance:** reports regenerate from retained records without rerunning the
experiment. Independent reference calculations check at least one discontinuous
cost model and one nonadditive error budget. Missing measurements remain missing;
no chart silently treats them as zero.

## Delivery order and release gate

1. **First-run path:** manifest wrapper, checked artifacts, standard report and
   the tested ten-minute guide.
2. **Reliable execution:** owned supervisor, attempt/event model and resource
   claims, then bounded sweep coordination using those guarantees.
3. **Research coordination:** board, digests, compatible transfers, decisive-test
   templates and the structured agent feedback packet.
4. **Selective computation:** calibrated cheap gates; forecast stopping only
   after separate trajectory validation. Advisory forecasts can ship earlier.

Run a reproducible end-to-end comparison on the same declared experiments and
hardware: manual baseline versus the wrapper/sweep/board workflow. Publish
onboarding time, manual interventions, duplicate work, compute, result latency,
missed accepted candidates, diagnosis time and artifact-check outcomes. Report
the workloads and hardware; do not extrapolate a tiny fixture to millions of full
circuit simulations.

The minimal v0.4 release gate is a researcher completing the first three milestones
on existing numeric and circuit-generator scripts without writing an adapter.
If a milestone remains incomplete, publish the limitation explicitly instead of
describing disconnected APIs as an end-to-end workflow. Forecast pruning may stay
experimental without blocking a useful first release.
