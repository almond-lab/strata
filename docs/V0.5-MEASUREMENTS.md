# Measurement costs, phase preservation, and bounded verification

The measurement paths use three separate kinds of evidence: expected execution
counts, exact boundary equality, and exhaustive contract verification. A cheaper
expected gate count does not establish equality, and an exact boundary receipt
does not establish a resource minimum.

## Static and expected execution counts

Static accounting remains the default. `--accounting expected` is available on
`restructure`, `search`, `optimize`, and `evaluate-file`. It computes the expected
number of executed instructions and paid gates under this explicit model:

- Each native HMR instruction supplies an independent, uniform primitive outcome.
- `BIT_STORE0`, `BIT_STORE1`, and `BIT_INVERT` produce deterministic Boolean
  functions of those primitives and the initial classical bits.
- `PUSH_CONDITION` snapshots its bit. Nested scopes and an instruction's own
  condition are conjoined as Boolean functions of the same primitives.
- Initial external classical bits have no implicit probability distribution.

These are native basis-trajectory assumptions. They do not describe the outcome
distribution of every possible quantum instrument or arbitrary quantum state.

Correlations remain part of the calculation. For example:

```text
HMR q3 b0
PUSH_CONDITION if b0
CCX q0 q1 q2 if b0
POP_CONDITION
```

The CCX has static count 1 and expected count `1/2`, because its two conditions
are the same event. Two independent outcome conditions give `1/4`. An outcome
conjoined with its complement gives zero. Nonlinear derived conditions, such as
the AND of two outcomes, use the same exact decision-graph calculation.

To assign a distribution to external bits, supply a JSON file with a joint
distribution. For example, this declares two perfectly correlated bits:

```json
[
  {"values": {"b0": 0, "b1": 0}, "probability": "1/3"},
  {"values": {"b0": 1, "b1": 1}, "probability": "2/3"}
]
```

```sh
strata restructure input.kmx --out run \
  --accounting expected --external-distribution external-bits.json
```

Every row must assign the same declared bits, and nonnegative rational weights
must sum exactly to one. An unspecified bit remains arbitrary. A gate expectation
can still be known if averaging the HMR outcomes removes dependence on that bit;
otherwise its expectation is unknown. The resource wrapper refuses expected
accounting when any required additive expectation is unknown. It never silently
substitutes static counts or treats an external bit as fair.

The Python entry points are
`strata.accounting.conditional_gate_accounting` and `measured_resources`.
The detailed receipt contains per-instruction activation probabilities, static
and expected gate counts, and exact rational strings. The resource wrapper
retains these strings in `expected_exact` and provides numeric values to the
existing objective evaluator. Quantum control values do not discount a CCX: its
execution cost depends on its classical activation.

Physical `Q` and native `reaction_depth` retain their static definitions.
Register declarations use the SDK's instruction weights; a text line is not
automatically an executed instruction. A formula applied to expected counts is
not generally the expectation of a nonlinear per-run cost formula. Decision
node, variable, probability-work, distribution-row, and operation budgets remain
explicit; budget exhaustion produces unknown accounting.

For a selected episode, optimization prices the candidate after inserting it
into the complete parent. This preserves the prefix's outcome correlations and
the parent's physical width in the objective.

## Phase-preserving segment construction

`resynthesize_measured_lookup` can improve supported arithmetic segments inside
an episode with a nonzero external sign or an outstanding HMR phase debt. It
preserves that phase exactly. It does not label the debt discharged, remove the
measurement, or infer a missing repair.

The constructor retains measurement and classical-control boundaries, proves
each replaced segment, and independently compares the complete result. The
comparison includes quantum outputs, classical outputs, exact sign, and ordered
measurement provenance: physical wire, destination bit, activation, and measured
value. Dirty outputs remain arbitrary. Declared clean workspace must satisfy
the constructor's restoration requirements. An unconditional HMR supplies a
later zero fact; a conditional HMR does not grant an unconditional zero lease.

`resynthesize_supported_segments(..., mode='direct'|'phase'|'lookup')` exposes
the same bounded mechanism to the constructor registry. Successful receipts say
`construction_scope: local_segment_resynthesis`. These local gains are distinct
from whole-function materialization-bank discovery.

The whole-episode XOR-table extractor still requires its stronger contract,
including zero phase and target-independent deltas. Its refusal to extract a
table is therefore not a veto on an independently proved local replacement.

## Measured cleanup in whole-function schedules

Whole-output XOR/AND schedules can use a different, explicitly checked rule.
When a live helper currently holds exactly the product of two available affine
operand values, HMR can erase it. The compiler prepares the same operand basis,
applies the outcome-conditioned CZ repair, and restores that basis. A canonical
value proof checks the actual prefix before each measured erasure. Dirty helpers,
overwritten parents, unavailable operands, and unsupported preparations do not
receive this rule. The complete reverse-compute alternatives remain available.

Fresh outcomes are allocated above the full parent's classical bit namespace,
including bits outside a selected episode. `introduced_private_bits` identifies
only these compiler-generated outputs. Existing classical outputs require the
user's explicit `internal_bits` declaration. Final checking proves each
construction's public values and sign independently of all its outcomes; it does
not couple different measurement histories or claim general channel equality.

The schedule bill includes helper allocation, operand preparation/restoration,
HMR instructions, repairs, classical width, and native reaction depth. The SDK
objective determines which gate types are priced; a correction containing CCZ
still contributes its static or expected paid cost. The compiler does not infer
that measurement or phase repayment is physically free. It chooses between
emitted reverse and measured alternatives using the full parent objective.

Both bounded truth-row witnesses and symbolic algebraic DAGs reach this path.
The symbolic path independently replays every final output polynomial and then
checks the emitted full boundary for every public input and formal outcome.
It does not manufacture an exact-minimum witness or enumerate a surrogate truth
table. A bounded native sample cross-checks the exact symbolic proof. The
12-input regression in `test_measured_boolean_synthesis.py` exercises actual
deep search through recovery, factoring, storage scheduling, and measured cleanup
with `truth_rows_enumerated: 0`. This is a supported whole-function family, not a
claim of universal algorithm discovery or a global native-cost minimum.

## Factored values reach constructors and queries

`constructor_semantics` can execute a quantum-only segment with canonical Boolean
decisions, cancel large intermediate expressions, and then expand only its final
deltas and phase into a bounded ANF. Unsupported segments remain in place. Final
projection has its own work and term limits; no truncated polynomial is used.

`projected_value_semantics` separately recovers final quantum values, classical
values, and phase for value queries, including measured episodes. It retains the
complete factored trajectory receipt rather than expanding every intermediate
measured value. Its measurement events refer to canonical decision roots, as
explicitly marked in the result. This value-query receipt is not the sparse
full-trajectory event schema. Complete trajectory equality continues to use the
independent factored comparator.

## Exhaustive lab verification

`strata.lab.exhaustive` accepts `branch_strategy='auto'`, `'full'`, or `'symbolic'`.
Full mode enumerates outcomes within its native trajectory budget. Auto mode
uses a proved affine-outcome reduction when available and can switch to bounded
symbolic verification when full execution would exceed the budget. Symbolic mode
proves every formal HMR outcome for each declared boundary input, including
nonlinear conditions, and separately replays outcome branch zero with kickmix.

The lab's phase proof represents exact dyadic exponents modulo two with Boolean
bit planes. Fractional phase is not rounded to a sign flag. Declared classical
registers participate in the input domain and output contract; dirty preservation
and clean-zero obligations come from the contract rather than the reference's
requested output values.

The receipt distinguishes represented branches, actual native trajectories, and
symbolically proved input cases. Operation and decision-apply budgets are global
across the input cases. Node, variable, phase-bit, trajectory, and timeout limits
can prevent certification. A shard remains sample evidence even if every case
inside that shard passes. Symbolic outcomes avoid explicit branch enumeration;
they do not guarantee efficient decision graphs for arbitrary circuits.

The sign-only factored constructor backend and the lab's dyadic-phase verifier
have different supported phase families. Success in one does not expand the
other's scope. Independent-map checking with explicitly private measurement bits
is also a separate mode from branch-preserving constructor equivalence.

Focused validation is in `test_conditional_accounting.py`,
`test_measured_lookup.py`, `test_lookup_review.py`,
`test_factored_constructors.py`, and the symbolic/classical lab tests. These cover
constructed fixtures and declared bounded contracts. They do not certify an
unprovided original production circuit, its host verifier, or every pipeline
that uses the same gate families.
