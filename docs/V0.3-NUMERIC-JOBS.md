# Checkpointed numeric jobs and safe-candidate bets

`NumericJob` runs a pinned offline worker one bounded stage at a time. It stores completed checkpoints, units, reported metrics, worker receipts and wall-budget accounting in the ordinary `Store`. Reopening a saved job handle resumes from its last complete checkpoint. This is a synchronous local runner, not a cluster scheduler or a background daemon.

## Worker protocol

The worker receives one JSON request path as an argv element. The request identifies the job, attempt, stage, immutable base-artifact hash, parent-checkpoint hash, declared settings and metric units. `base_artifact` and `checkpoint` are staged file paths; the latter is `null` on the first stage unless an initial checkpoint was supplied. The worker must leave these inputs unchanged, write a new checkpoint inside its stage directory, and emit one JSON response on stdout.

For example, save this as `worker.py`:

```python
import json
import sys
from pathlib import Path

request = json.loads(Path(sys.argv[1]).read_text())
settings = request['settings']
state = (json.loads(Path(request['checkpoint']).read_text())
         if request['checkpoint'] else {'x': 0.0, 'iterations': 0})

# Replace this small numerical experiment with the actual bounded solver stage.
for _ in range(settings['iterations_per_stage']):
    state['x'] += settings['learning_rate'] * (settings['target'] - state['x'])
    state['iterations'] += 1
loss = abs(settings['target'] - state['x'])
Path('next.json').write_text(json.dumps(state))

print(json.dumps({
    'job': request['job'],
    'attempt': request['attempt'],
    'stage': request['stage'],
    'checkpoint_file': 'next.json',
    'metrics': {'loss': loss},
    'metric_kinds': {'loss': 'measured'},
}))
```

`metric_kinds` accepts `measured`, `fitted_trend`, `model` and `judgment`. Omitting it means the worker explicitly reports its numeric outputs as measurements; this is **worker-reported measurement**, not independent host acceptance. Label predictions and extrapolations accordingly. Only metrics labeled `measured` may trigger a stop or readiness rule. Metric names must exactly match the job's declared unit mapping.

## Create, run and resume

Run the controller from a normal source file with an installed Strata environment:

```python
import sys
from pathlib import Path
from strata.store import Store
from strata.numeric_jobs import NumericJob

store = Store('numeric-runs')
worker = Path('worker.py').absolute()
job = NumericJob.create(
    store,
    contract='example-fit-v1',
    base_artifact=store.blob(b'fixed example input'),
    command=[str(Path(sys.executable).absolute()), str(worker), '{request}'],
    dependencies=[worker],
    metric_units={'loss': 'dimensionless'},
    settings={'target': 1.0, 'learning_rate': 0.01,
              'iterations_per_stage': 500},
    max_stages=8,
    max_wall_seconds=120,
    stage_timeout=10,
    memory_bytes=2 * 1024**3,
    max_file_bytes=128 * 1024**2,
    max_output=1_000_000,
    stop_rules=[{'metric': 'loss', 'op': '>', 'value': 2.0,
                 'after_stages': 1}],
)
Path('job-id.txt').write_text(job.id)
print(job.run(stages=1))
```

In a later process:

```python
from pathlib import Path
from strata.store import Store
from strata.numeric_jobs import NumericJob

store = Store('numeric-runs')
job = NumericJob(store, Path('job-id.txt').read_text().strip())
print(job.status())
print(job.run(stages=7))
```

Creating another job makes a distinct run. Resuming requires the existing handle. Its settings, units, dependencies, budgets and rules are immutable; changing them requires a new job, optionally initialized from an existing checkpoint blob. Executable invocation preserves virtualenv paths. The executable, virtualenv configuration/package metadata and explicitly declared dependencies are checked before and after each stage. Metadata identity does not pin every transitive package source byte; declare additional source/data dependencies explicitly.

A nonblocking file lock prevents two processes from advancing the same job simultaneously. A completed checkpoint and its finish record commit atomically. Failed workers retain the previous complete checkpoint. If a process disappears before writing a finish record, its full reserved timeout is charged on resume. Controller implementation hashes are also frozen; resume after a controller upgrade requires a new job initialized from the retained checkpoint. Resource limits apply through the mandatory offline bubblewrap boundary. Address-space and CPU limits are per process, not aggregate worker-pool limits.

## Automatic readiness and local certification

A job can automatically package a ready checkpoint and run the existing Line lab/build/full-verification gates. Readiness rules and a **trusted, source-pinned** packager must be declared when the job is created. The packager receives a `NumericCheckpoint` containing the checkpoint bytes/hash, stage, metric evidence and job identity; it must return a real frozen `Line`.

For a declarative project with task `fit`, editable component `numbers`, and component file `numbers.json`, a controller's packager can be:

```python
import tempfile
from pathlib import Path
from strata import open as open_project
from strata.callbacks import PinnedCallback

PROJECT_FILE = Path('/absolute/project/strata.toml')

def package_checkpoint(checkpoint):
    project = open_project(PROJECT_FILE)
    base = project.task('fit').base_design()
    with tempfile.TemporaryDirectory() as temporary:
        candidate = Path(temporary) / 'numbers.json'
        candidate.write_bytes(checkpoint.checkpoint_bytes)
        # Declarative Lines freeze replacement bytes during open_line.
        return project.open_line(
            base, 'co-design-numerics', ['numbers'],
            implementation={'files': {'numbers.json': str(candidate)}},
        )

packager = PinnedCallback(package_checkpoint, dependencies=[PROJECT_FILE])
```

The configured component schema and independent verifier must accept the checkpoint's actual data format. Pass these extra arguments to `NumericJob.create`:

```python
readiness_rules=[{'metric': 'loss', 'op': '<=', 'value': 1e-6}],
promotion=packager,
```

After each complete checkpoint, all readiness rules must match measured metrics. A triggered stop rule takes precedence. On readiness, `run` invokes the pinned packager and ordinary Line gates automatically. A resumed process supplies the same pinned callback with `job.run(stages=7, promotion=packager)`. Its identity must match the stored policy.

Successful certification records the checkpoint-to-Line-to-design/certificate connection and project-store location. `status='promoted'` means a **local certified design** exists; it is not an external submission or proof that the portfolio score improved. Existing safe designs remain stored and portfolio selection stays separate. Failed packaging or independent verification preserves the checkpoint, records the failure and raises. A subsequent run can retry certification from that checkpoint. Certification uses the task's own verifier limits and is outside the numeric worker's stage-wall budget.

The packager is trusted integration code, like an existing `PinnedCallback`; it does not run as untrusted worker code inside the sandbox. Pin its source and relevant project/configuration dependencies. Make packaging idempotent for a checkpoint hash: a process interruption between creating a project design and recording the job's promotion can require retrying the local certification. This is not a distributed exactly-once guarantee. No remote scheduler, continuous watcher, cluster lease or external publication is installed by this API.

## Compare bets while retaining a safe fallback

`score_bets` computes the geometric mean of `baseline_cost / candidate_cost` over the supplied complete task set. It never averages task costs before applying this formula. Each bet supplies conditional success costs and an explicitly labeled probability. Failure retains the supplied safe portfolio; a worse success outcome is also declined in the expected-score calculation.

```python
from strata.numeric_jobs import score_bets

comparison = score_bets(
    current_costs={'a': 10.0, 'b': 20.0},
    baseline_costs={'a': 20.0, 'b': 40.0},
    bets=[{
        'id': 'longer-fit',
        'costs': {'a': 2.5},
        'cost_evidence_kind': 'model',
        'probability': {'value': 0.25, 'evidence_kind': 'judgment'},
        'remaining_compute_seconds': 600,
    }],
)
```

Here the supplied safe score is 2, conditional success score is 4, and expected score under the stated judgment is 2.5. These are conditional calculations, not measurements or certified probabilities. Claims of `measured` probability or success cost require an existing evidence artifact and `store=...`; an artifact establishes retained provenance, not statistical calibration. The caller must supply actual retained certified costs for a portfolio to deserve the word “safe.”
