# Shared numeric candidates and priced pipelines

[numeric_candidates.py](../src/strata/numeric_candidates.py) supplies a common
candidate representation, a pinned reference scorer, an optional calibrated
fast path, derivative diagnostics and composable preparation stages. The host
supplies the mathematics and acceptance rules. There is no built-in task metric
or automatic derivative of a discrete rounding procedure.

## One format across agents

`NumericCandidate.create(store, contract=..., arrays=..., units=...)` stores
named finite numeric arrays without pickle/object data. Each component records
shape, dtype, unit, role, data hash and a boolean trainable mask. Parameters,
stage, actor, settings and parent candidate identify the lineage. Arrays and
masks are reloaded from checked blobs rather than trusted mutable metadata.

`candidate.id` names the immutable candidate record. `candidate.artifact_hash`
names stored manifest bytes that bind the complete component/mask hashes and
lineage; retain the referenced blobs with the manifest. `save()`,
`NumericCandidate.load(store, handle)` and `push(label)` support same-Store
handoffs. A candidate handle is not an external submission or a host certificate.

## Reference cost first, then a fast path

Save this example as a Python file before executing it: `PinnedCallback` needs
an actual source file to freeze. The example uses an illustrative quadratic,
not a host-specific metric.

```python
import numpy as np
from strata.callbacks import PinnedCallback
from strata.numeric_candidates import NumericCandidate, NumericScorer
from strata.store import Store

def reference(request):
    arrays = request["arrays"]
    smooth = float(np.sum(arrays["parameters"] ** 2))
    discrete = float(np.sum(arrays["words"].astype(float) ** 2))
    return {
        "metrics": {"error": smooth + discrete, "work": 4.0},
        "checks": {"finite": True},
        "partitions": {
            "sources": {"metric": "error", "unit": "error",
                        "terms": {"smooth": smooth, "discrete": discrete}}
        },
    }

def derivative(request):
    return {"kind": "continuous",
            "gradients": {"parameters": 2 * request["arrays"]["parameters"]}}

store = Store("/tmp/strata-candidate-example")
candidate = NumericCandidate.create(
    store, contract="illustrative-quadratic-v1",
    arrays={"parameters": np.array([1.0, 2.0]),
            "words": np.array([1, 2], dtype=np.int16)},
    units={"parameters": "amplitude", "words": "integer"},
)
scorer = NumericScorer(
    store, contract="illustrative-quadratic-v1",
    reference=PinnedCallback(reference), gradient=PinnedCallback(derivative),
    formula="error*10+work", metric_units={"error": "error", "work": "operations"},
)
assessment = scorer.assess(candidate)
assert assessment["cost"] == 104
checked = scorer.check_gradients(candidate, metric="error")
assert checked["passed"] and checked["evaluations"] == 4
moves = scorer.discrete_moves(
    candidate, [{"component": "words", "index": [1], "value": 0}]
)
assert moves["moves"][0]["cost_delta"] == -40
store.db.close()
```

A scorer callback receives candidate identity, arrays and parameters, and
returns exactly the declared metrics, explicit boolean checks and optional
attribution partitions. Each partition must name a metric, match its unit, and
sum to the complete reported value. Overlapping views are separate partitions;
their totals must not be added together. The exact supplied `Formula` prices
the metrics before the score is stored. The receipt retains the artifact hash,
source identity, units, checks and frozen/trainable counts.

Configure `fast=PinnedCallback(fast_function)` and call
`scorer.calibrate(candidates, atol=..., rtol=..., cost_atol=..., cost_rtol=...)`
before `assess(candidate, fast=True)`. Metric and attribution agreement alone
are insufficient: final cost has its own tolerances, zero by default. This
catches amplification through the objective. Calibration is empirical on the
listed artifacts; source/dependency changes invalidate it. Fast results remain
`model`, and final reference/host checks remain required on a selected candidate.

## Continuous diagnostics and discrete choices

`gradients(candidate, metric=...)` requires a pinned plugin that labels its
output `continuous` or `surrogate`. A plugin-provided gradient is initially an
unvalidated model. Continuous derivatives of integer/boolean components are
rejected. A labelled surrogate does not become an exact discrete derivative.

`check_gradients` compares continuous real-valued, trainable coordinates with
central differences of the pinned reference metric. It retains probe candidates,
parent lineage and score handles, with at most 16 reference evaluations. A
budgeted partial check remains `bounded`. Consistency at those probes is not a
global derivative theorem, automatic host autodifferentiation, or acceptance.
The objective's chain rule is not inferred automatically from metric gradients.

`discrete_moves` evaluates caller-listed integer/boolean coordinate changes
under the reference and prices their full cost differences. It includes the
baseline in its limit of at most 16 reference evaluations, rejects frozen or
out-of-range changes, and preserves each probe's lineage. These are exact
listed moves, not a claim of global discrete optimality.

## Compose the actual preparation order

Create `NumericStage(name, PinnedCallback(callback), settings=...,
invariant_metrics={metric: absolute_tolerance})` objects and pass their ordered
list to `NumericPipeline(store, scorer, stages)`. A stage receives a loaded
candidate, copied settings and the previous score. It returns a candidate in
the same Store with the previous candidate as parent, or the unchanged candidate.
Use stages for caller-supplied ordering, picking, fitting, repair or normalization.

The pipeline pins callback identities, settings, order and invariant tolerances.
Frozen parameter values cannot change, and a child cannot make a frozen parent
parameter trainable. A claimed neutral transformation must preserve the declared
reference metrics within the pinned tolerances. Mutating a plugin's copy of the
previous score cannot change this comparison.

`pipeline.run(candidate)` reports cost after the complete declared preparation
pipeline, not just the attractive intermediate fit. Every successful stage
creates a checkpoint. `run(original_candidate, resume=checkpoint_handle)` checks
pipeline/original/stage scope and resumes from that candidate. Failures retain
their reason and last checkpoint. This is local experiment state, not an
exception to the independent host verifier.
